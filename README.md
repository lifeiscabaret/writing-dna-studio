# 🧬 Writing DNA Studio

> Extract the **DNA of your writing voice**, then rewrite any message so it sounds
> unmistakably like *you* — across casual texts, social posts, professional emails,
> and blog paragraphs.

A **Microsoft Agents League Hackathon** entry in the **Creative Apps** category.
Built with **Next.js 16 + TypeScript + Tailwind v4**. **Offline-capable with an
optional Azure AI Foundry provider** — the deterministic engine runs with no
account or keys, and an Azure-backed rewrite (gpt-5-mini) activates when
configured, always with a local fallback.

Writing DNA Studio is a **chat-first, consent-based personal writing assistant**:
you bring *your own* writing, the app builds a **temporary** style profile from it,
and then rewrites new text in that voice. Nothing is stored server-side, and no
real personal or confidential data is required.

---

## 🧭 Chat-first flow

The studio is a chat-style assistant with three stages:

1. **Landing** — a self-playing demo chat; tap **"Teach it my voice"** to start
   (or **"Watch it work"** to load a synthetic demo voice first).
2. **Voice setup** — paste a few of your own messages and tap **"Teach my voice"**;
   the app replies with your voice chips and a collapsible **"View full voice profile"**.
3. **Compose** — type a rough draft and tap **"Make it sound like me"**. The reply
   shows the rewrite, **Copy** / **Share** buttons, one-tap refinement chips
   (Warmer · Shorter · More confident · More casual · More polished), and a
   collapsible **"Agent pipeline"** trace with the evaluation summary.

Your own samples are the **primary path**; the synthetic demo voice is offered only
for safe testing (**"or use a demo voice"**).

## ✨ What it does

1. **Writing sample input** — paste a few sentences in your *own* natural voice (English or 한국어).
2. **Writing DNA extraction** — builds a **"Your Writing DNA"** card with tone, rhythm, emoji usage, formality, warmth, directness, and signature expressions.
3. **Style transfer rewrite** — any source text is rewritten to match that DNA.
4. **Output format selector** — Casual message · SNS post · Professional email · Blog paragraph.
5. **Azure-backed rewrite** — when configured, the rewrite is generated by **Azure AI Foundry (gpt-5-mini)** with the voice sample, format, grounded guidance, and safety rules as constraints; a local deterministic engine is the strict fallback. The output shows which engine produced it.
6. **Style match score** — the rewritten output is re-fingerprinted and scored against your DNA, with a per-axis breakdown.
7. **Knowledge grounding** — the **"Ground with style guide"** toggle grounds the rewrite in a synthetic style guide (local by default; optional Foundry-backed retrieval behind a flag). See *Microsoft IQ / Foundry IQ grounding approach*.
8. **Language preservation** — output stays in the input language; Korean text keeps Korean conventions (e.g. `안녕하세요, …님` / `감사합니다 … 드림`, Korean hashtags) and never gets English greetings or sign-offs.
9. **Synthetic demo voices** — five descriptive style presets live in `profiles.ts` (*Friendly Creator, Data-Driven Analyst, Calm Editor, High-Energy Founder, Casual Messenger*); the UI surfaces one as the demo voice for safe testing.

### The five style axes (Writing DNA)

| Axis | 0 ⟶ 100 |
|------|---------|
| **Formality** | Casual ⟶ Formal |
| **Warmth** | Reserved ⟶ Warm |
| **Directness** | Elaborate ⟶ Direct |
| **Energy** | Calm ⟶ Energetic |
| **Playfulness** | Serious ⟶ Playful |

Each axis is derived from measurable signals (sentence length, contraction rate,
emoji rate, exclamation/question rates, lexical diversity, hedging, intensifiers,
formal/casual vocabulary, …), so the score is **explainable** rather than a black box.

### Agentic architecture

This MVP includes a lightweight agent pipeline layer that runs alongside the
existing deterministic rewrite engine while preserving the current UI and
existing API contract.

The new agent pipeline is:

- **Voice Profile Agent** — wraps `extractWritingDNA()` to build a voice
  fingerprint and surface core traits.
- **Intent Agent** — infers task type, user goal, recommended tone, and a
  confidence score from the source draft and selected format.
- **Knowledge Grounding Agent** — when Azure / Microsoft Foundry is enabled,
  retrieves the 3–5 most relevant rules from a synthetic style guide and passes
  them into the rewrite as constraints; otherwise falls back to a local synthetic
  mock index. See *Microsoft IQ / Foundry IQ grounding approach* below.
- **Rewrite Agent** — runs the Azure-backed generation step (with the voice
  sample, format, grounded guidance, and safety rules as constraints), preserving
  the deterministic engine as a strict fallback.
- **Evaluation Harness Agent** — scores the output on voice match, meaning
  preservation, format fit, safety/consent, and readability.

The deterministic engine still runs locally as the offline fallback and scorer,
while the Azure-backed grounding and rewrite steps activate when configured —
without changing the client or API surface.

### Microsoft Foundry integration

This app can run entirely locally with the deterministic engine by default.
An optional Azure provider mode is available via environment variables:

- `AZURE_FOUNDRY_ENABLED=true` — enables the **Azure rewrite provider** (the main, most valuable step).
- `AZURE_GROUNDING_ENABLED=false` — when `true`, enables the **Azure/Foundry-backed grounding** call. **Off by default** for demo speed.
- `AZURE_OPENAI_ENDPOINT`
- `AZURE_OPENAI_API_KEY`
- `AZURE_OPENAI_DEPLOYMENT`
- `AZURE_OPENAI_API_VERSION`
- `AZURE_REWRITE_TIMEOUT_MS=15000` — rewrite call timeout before local fallback (default `15000`; raise to `30000` for testing).
- `AZURE_REWRITE_REASONING_EFFORT=minimal` — reasoning cap for the rewrite. `minimal` keeps gpt-5 style-transfer fast (~2–6s); raise to `low`/`medium` only if quality needs it.

**Latency design (for live-demo stability).** Knowledge grounding defaults to
**local synthetic guidance** (deterministic, no network call), so only the
**rewrite** step calls Azure. The rewrite is tuned for speed: a **compact prompt**
(voice sample capped at 500 chars — 300 on the short-draft fast path — plus ≤3
guidance bullets and only the selected refinement), a **small output budget**
(500–800 tokens), and **`reasoning_effort: minimal`**, which is the dominant
speed lever for gpt-5 reasoning deployments. In practice rewrites now return in
**~2–6s** (down from the earlier >15s timeouts). The rewrite call has a
**15-second timeout** (configurable) and the optional Foundry grounding call an
**8-second timeout**; either falls back to the local deterministic engine, which
is strictly preserved for safety and reliability.

### Microsoft IQ / Foundry IQ grounding approach

The Knowledge Grounding Agent grounds the rewrite in a trusted **synthetic** style
guide. For **live-demo stability** the default path is **local synthetic
guidance**; a **real, provider-backed Foundry grounding** path is supported behind
an explicit flag. We do **not** claim full enterprise Foundry IQ integration.

**What is actually implemented today:**

- The knowledge source is a hand-authored **synthetic style guide**
  (`docs/knowledge/writing-dna-style-guide.md`) — consent rules, per-format
  guidance, refinement rules, safety rules, and short-sample confidence rules.
  It contains **no real private data**.
- **Default (local synthetic guidance).** The agent selects the 3–5 rules most
  relevant to the request (format + intent + refinement + safety) **deterministically
  from the guide, with no network call**, and feeds them into the rewrite prompt as
  **hard constraints**. The trace reads *"matched synthetic style guidance."*
- **Opt-in (`AZURE_GROUNDING_ENABLED=true`).** The agent instead asks the Azure /
  Microsoft Foundry provider to retrieve those rules from the same guide. On
  success the trace reads *"Microsoft Foundry grounding connected"*; on
  failure/timeout it falls back to the local synthetic guidance
  (*"Foundry grounding fallback"*).
- Either way, the rewrite model is told to follow, in priority order: the user's
  voice sample, the selected format, the grounded guidance, and the safety rules.
  The **rewrite step itself stays Azure-backed** (`AZURE_FOUNDRY_ENABLED=true`) with
  a local deterministic fallback.

**What a production version would change:**

- Replace the synthetic guide with a **Microsoft Foundry IQ knowledge base**
  connected to **user-approved** sources — the user's own consented writing
  history, saved preferences, or an organization's style guide — with real
  retrieval and citations.
- Persist consented profiles instead of the current temporary, session-scoped
  ones.

In short: live demo = **local synthetic grounding + Azure rewrite** for stability;
Foundry-backed grounding is real and available behind `AZURE_GROUNDING_ENABLED=true`;
only the **knowledge source is synthetic** in this MVP.

### The engine (`src/lib/dna/`)

| File | Responsibility |
|------|----------------|
| `types.ts` | Shared contracts (`WritingDNA`, `RewriteResult`, `StyleMatchScore`, …) |
| `lexicon.ts` | Hand-tuned word lists & substitution tables |
| `extract.ts` | `extractWritingDNA()` — sample → fingerprint (deterministic, offline) |
| `rewrite.ts` | `rewriteInStyle()` — transparent transform pipeline, reports every step |
| `score.ts` | `scoreStyleMatch()` — re-extracts the output and compares axis-by-axis |
| `knowledge.ts` | Local mock keyword index — the synthetic fallback for grounding |
| `formats.ts` | The four output formats |
| `profiles.ts` | Five **synthetic** demo *styles* (for safe testing) |
| `index.ts` | Engine orchestrator + public exports |

The agent pipeline and Azure provider live alongside the engine:

| File | Responsibility |
|------|----------------|
| `src/lib/agents/runAgentPipeline.ts` | Orchestrates the agents end-to-end |
| `src/lib/agents/knowledgeGroundingAgent.ts` | Local synthetic guidance (default) / optional Foundry grounding |
| `src/lib/providers/azureFoundryProvider.ts` | Azure AI Foundry (gpt-5-mini) rewrite + guidance calls, timeouts, fallback |
| `docs/knowledge/writing-dna-style-guide.md` | The **synthetic** style-guide knowledge source |

**Why a deterministic engine?** It makes the hackathon demo instant, free, and
reproducible, and it gives every score a human-readable explanation. Crucially,
each function's signature matches what an LLM- or Foundry-IQ-backed implementation
would expose — so swapping in the real providers requires **no UI or API changes**.

## 🔌 Microsoft Foundry IQ integration plan

**Today:** grounding is a real, provider-backed step against a **synthetic** style
guide (`docs/knowledge/writing-dna-style-guide.md`) — local synthetic guidance by
default, optional Azure/Foundry-backed retrieval behind `AZURE_GROUNDING_ENABLED=true`
(see *Microsoft IQ / Foundry IQ grounding approach* above). The **knowledge source**
is the only synthetic piece; the mechanism is wired end-to-end.

**In production, Microsoft Foundry IQ would serve as the grounded *style knowledge
layer*** — the durable, consented home for a user's voice. Foundry IQ (the knowledge
layer in Azure AI Foundry) provides agent-ready retrieval over trusted, indexed
knowledge sources with built-in citations. The planned swap:

1. **Index** the user's own **consented** corpus in a Foundry IQ knowledge base —
   their past writing, brand/style guides, and voice notes — replacing the synthetic
   guide as the grounded style source.
2. **Point** the Knowledge Grounding Agent at the Foundry IQ retrieval API instead
   of the synthetic guide (the agent's contract already returns the same shape).
3. **Map** the returned passages + citations onto the existing `KnowledgeFact`
   shape (`claim` / `source` / `confidence`) — already a 1:1 fit — and render real citations.
4. **Persist** consented profiles across sessions instead of the current
   temporary, session-scoped ones.

The deterministic engine stays as the fast offline fallback and as a guardrail/scorer.
**No Azure resources are required to run the offline demo**; the Azure provider is
optional and activates only when configured.

## ⚠️ Synthetic data disclaimer & consent

**This app is consent-based by design.** The intended use is that you extract a style
profile from **your own** writing, with your knowledge, into a **temporary** profile
that lives only in the current session.

**The demo styles are synthetic and exist only for safe testing.** The five presets in
`src/lib/dna/profiles.ts` (*Friendly Creator, Data-Driven Analyst, Calm Editor,
High-Energy Founder, Casual Messenger*) are **descriptive writing styles, not
characters or people** — their samples are fictional and authored for this demo, and
do not represent any real person or any real private text. The mock knowledge "facts"
in `knowledge.ts` are likewise invented placeholders (note their `mock://` sources).

When you paste your **own** sample it is held only in the current session and is
**never stored**. In the **offline default**, it is processed only in your browser
and this app's own server route. When the **optional Azure provider** is enabled
(`AZURE_FOUNDRY_ENABLED=true`), a truncated voice sample and your draft are sent to
**your own Azure AI Foundry resource** to generate the rewrite — no other
third-party service is involved, and the app falls back to the fully-local engine
if Azure is unavailable.

## 🧑‍⚖️ How judges can run this project

The app runs **without any secrets** — Azure is optional.

```bash
npm install
npm run dev          # → http://localhost:3000
```

- **No Azure needed.** Out of the box the app works fully on the **local
  deterministic fallback** — voice extraction, grounding (local synthetic
  guidance), rewrite, scoring, and the agent pipeline all run with no keys.
- **Optional Azure rewrite.** Only if you want to see the Azure path live, copy
  the template and add **your own** Azure AI Foundry credentials:
  ```bash
  cp .env.example .env.local   # then fill in AZURE_OPENAI_ENDPOINT + AZURE_OPENAI_API_KEY
  ```
  Set `AZURE_FOUNDRY_ENABLED=true` and restart `npm run dev`.
- **In the demo video**, the Azure AI Foundry rewrite (gpt-5-mini) is shown
  end-to-end. Reviewers can reproduce it with their own credentials, or evaluate
  the identical UX on the local fallback without any setup.

## 🧪 API reference

| Endpoint | Body | Returns |
|----------|------|---------|
| `POST /api/extract` | `{ sample }` | `{ dna: WritingDNA }` |
| `POST /api/rewrite` | `{ styleSample, sourceText, format, useKnowledge?, recipientName?, senderName?, refinement? }` | `AgentPipelineResult` (rewrite + `agentTrace`, `evaluation`, `provider`) |

`format` ∈ `casual-message` · `sns-post` · `professional-email` · `blog-paragraph`.
`refinement` ∈ `warmer` · `shorter` · `more confident` · `more casual` · `more polished`.
